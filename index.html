Workload identity for AI agents

Delegate a slice of your identity.
Never hand over the keys.

Your coding agent runs with your full identity — every .env, every credential on disk. llm-secrets gives it an attenuated, signed bearer token scoped to one secret, one repo, one branch, five minutes. It can use what you granted. It cannot widen the grant.

The problem

The secrets managers you already use weren't built for an agent reading your disk.

They all have a get command that prints plaintext to stdout. In an LLM context that's a leak — persisted to transcripts, provider logs, and training data. Telling the agent "please don't" is a request, not security.

✕ leaks on read

.env · sops · doppler run

Output raw secrets to stdout. Game over the moment an agent reads them.

✕ patches the symptom

proxy daemons

Sit between agent and store and try to filter. A behavioural patch on a structural problem.

✕ not security

honour systems

"Agent, please don't look at the .env." A polite request the model is free to ignore.

The approach — capability delegation

The requester carries no secret material. Only a narrowed grant of authority.

The same pattern that took cloud computing from "VM with a password" to workload identity with IAM — and the primitive Tailscale and Fly.io use for service auth. Applied here to AI coding agents.

dev — mint & hand off
# Mint: scoped to one secret, 5 minutes, this branch, this agent
$ M=$(llms macaroon mint \
    --secret db_password \
    --ttl 5m \
    --branch main \
    --agent claude-code)

# Hand it to the agent — it inherits a slice of you, not all of you
$ LLM_SECRETS_MACAROON=$M claude

# Done, or something looks wrong? One command kills every derived token, O(1)
$ llms revoke-all → root key deleted · all macaroons invalidated
// encrypted at rest

age-encrypted store

X25519 + ChaCha20-Poly1305. The store on disk is ciphertext, not a convenience.

// who / where / what / when

Signed sessions

Every operation anchors to a tamper-evident, time-bounded claim — agent type auto-detected from the environment.

// allow-list policy

Declarative policy file

Drop a .llm-secrets-policy.yaml at the repo root. Unmentioned keys are denied; deny short-circuits allow.

// append-only

Audit log

Every secret access recorded with the full claim set. Set LLM_SECRETS_AUDIT_STRICT=1 and a failed log write stops the operation.

// strict subset

MCP server mode

llms mcp exposes a subset of the CLI to agents. No MCP tool returns plaintext — the model can't ask for one.

// recipe layer

TOML profiles

Name a bundle of secrets and env mappings once: llms profile exec db -- psql. The profile is non-secret config; the macaroon carries the authority.

Architectural enforcement
No get
command.
Ever.

Plaintext leaves the binary through exactly two doors — and neither is stdout. It's verifiable in about 50 lines of source, not a convention you're trusting us to keep.

  • → exec --injectplaintext enters a child process's environment, never your terminal.
  • → peeka deliberately lossy, masked preview. Shape without value.

A test named no_get_command_exists fails the build if anyone adds one.

The surface

The commands you'll actually use.

The CLI is small on purpose. safe marks commands designed to run inside an agent context.

llms initCreate the age-encrypted store safe
llms set <key>Store a secret via hidden input safe
llms exec --injectRun a command with secrets injected safe
llms macaroon mintMint a delegated bearer token
llms profile execMint and exec from a named recipe
llms lease <key>Time-bounded access · exec --leased fails closed
llms auditView the append-only access log safe
llms revoke-allEmergency killswitch · O(1)
